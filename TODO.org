* Todo [1/9]
- [ ] Have the ~louis~ binary depend on the ~louis~ library instead of
  compiling the same sources again
  - ~src/main.rs~ declares its own ~mod parser~, ~mod translator~,
    ~mod metadata~, ~mod test~ and ~mod yaml~; ~src/lib.rs~ declares an
    overlapping ~mod parser~, ~mod translator~, ~mod emphasis~ and
    ~mod hyphenation~. Both targets therefore compile the same sources,
    and to the compiler the resulting types are unrelated: the
    binary's ~parser::TableError~ is not the library's.
  - Consequences visible today:
    - ~main.rs~'s ~TableLoadError~ is a variant-for-variant copy of
      ~lib.rs~'s public ~TranslationError~, and cannot simply use it
    - dead-code warnings differ between the two builds, so the same
      function is "never used" in one target and used in the other,
      which makes the warnings hard to act on (see
      ~with_display~/~DisplayTable::compile~)
    - anything the CLI needs has to exist twice or be duplicated
  - The blocker is deciding what becomes public API. The CLI reaches
    for ~parser::table_expanded_in~, ~TranslationPipeline~,
    ~ResolvedTranslation~, ~AnchoredRule~ and ~TranslationStage~, none
    of which ~lib.rs~ exports today, and the library API is explicitly
    not stable yet. Same question as exposing a display table on
    ~Translator~.
  - Blocks translating from a metadata query: ~metadata~ is a module of
    the binary only, so ~Translator~ cannot reach the index at all. See
    the entry below.
- [ ] Let a ~Translator~ be built from a metadata query, as liblouis
  allows
  - ~metadata::Index~ exists and the ~query~ subcommand and the YAML
    test harness both use it, but it is declared in ~main.rs~, not in
    ~lib.rs~, so nothing in the library API can reach it. Moving it is
    part of the binary/library split above.
  - ~Index::build~ takes the ~SearchPath~ to walk, so the index itself
    carries no assumption about where tables live. What does is
    ~metadata::index()~, the convenience the CLI and the harness use: a
    process-wide ~LazyLock~ over ~LOUIS_TABLE_PATH~, built once from
    whatever the environment said the first time anybody asked.
  - That accessor must not become the way a ~Translator~ resolves a
    query. A host using ~Translator::with_search_path~ supplies its own
    directories, and the ambient index would quietly answer from
    somewhere else instead; two different search paths in one process
    cannot both be served by it either. Either call ~Index::build~ with
    the caller's search path and pay the walk, or cache per search path.

- [ ] Normalize input text to a canonical Unicode form
  - NFC normalization was tried (input at the start of the pipeline,
    plus rule patterns) but reverted: it fixed tables that define
    rules for precomposed characters (e.g. pt-pt-g1.utb), but broke
    tables that define rules for standalone combining characters (IPA,
    Hebrew, Yiddish) with no table-side workaround available. No
    normalization happens today. NFD normalization is a promising
    alternative — it decomposes all input, so combining marks stay
    explicit and precomposed rules still match via longer trie paths.
  - See [[file:doc/adr/0004-unicode-normalization.org][ADR-0004]]

- [ ] The "standing alone" check for ~word~ and ~contraction~ rules
  (liblouis's ~inSequence~), used by tables with a ~seqdelimiter~
  (~en-ueb-g2~, ~fil-g2~, ~xh-za-g2~). Before the word, skip
  ~seqbeforechars~, then require a space, a ~seqdelimiter~ or the
  start; after it, skip ~seqafterchars~ and ~seqafterpattern~ strings
  (case-sensitive), then require a space, a ~seqdelimiter~ or the end.
  louis-rs collects the ~seq*~ classes but uses none of them, and
  ~seqafterpattern~ still compiles to nothing; the trie's word
  boundaries (space or punctuation) give the same result for the cases
  tried. Implementing it as a retain would drop the weight of the
  boundary transitions, which ~Rank~ compares before precedence and
  definition order.
- [ ] Backward ~decpoint~ has no "digit follows" check. ~Rank~
  compares weight before precedence and definition order, and the
  check, as an ~End~ transition, would add weight: ~decpoint . 46~

  would come out as ".ई" instead of "खी". Without it, ⠨ reads as "."
  where no digit follows, now that the earlier-defined ~decpoint~
  wins the tie: 2 of ~ml.yaml~'s backward tests (⠍⠥⠨⠰ gives "മു.ം"
  instead of "മുഖം"). liblouis checks the digit and then falls through
  its chain to the next rule.
